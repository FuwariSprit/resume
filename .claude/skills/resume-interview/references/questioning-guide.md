# 深掘り質問集

`/resume-interview` の対話で、掘り方に詰まったとき・相手の答えが浅いときに使う質問文例です。
そのまま読み上げる必要はありません。相手の答えに合わせて言い換えてください。

## 案件の輪郭を掴む

- そのシステムは、誰がどんな目的で使うものでしたか
- toC向けですか、toB向けですか。社内向けですか
- 規模感はどのくらいでしたか（ユーザー数、PV、データ量、取引額など、言える範囲で）
- そのプロジェクトは、そもそも何のために始まったんですか
- あなたが参加した時点で、そのプロジェクトはどういう状態でしたか
- プロジェクトの中で、あなたが最初に任されたことは何でしたか

## チームと自分の担当を切り分ける

- チームは何名で、内訳はどうでしたか（バックエンド何名、フロント何名、PM、デザイナーなど）
- 社外のメンバー（協力会社、クライアント側の担当者）はいましたか
- そのうち、**あなた自身が手を動かしたのはどの部分**ですか
- いまの説明の主語は「チーム」でしたが、あなた個人が担当したところはどこですか
- 他のメンバーがやったことと、あなたがやったことの境目はどこですか
- あなたが決めたことと、決まっていたことに従ったことを分けると、どうなりますか
- 「リード」とのことですが、具体的にどういう動き方でしたか（設計を書いた、レビューした、方針を決めた）

## 技術の使い方を具体化する

- そのプロジェクトで使われていた技術と、あなたが実際に触った技術は同じですか
- 触っていないけどプロジェクトでは使われていた技術はありますか
- <技術名>は、**どの場面で、何をするために**使いましたか
- <技術名>で作ったものの中で、一番手応えがあったのはどれですか
- その技術のどこまで踏み込みましたか（使っただけ / 設定を調整した / 内部を読んだ / 拡張した）
- ドキュメントを見れば書ける、のか、何も見ずに設計から書ける、のか、どちらに近いですか
- パフォーマンスやエラーで困ったことはありましたか。どう調べて、どう直しましたか

## 「なぜ」を追撃する

1段目:

- なぜその技術（やり方）を選んだんですか
- なぜそのタイミングでそれに着手したんですか

2段目（1段目の答えが浅いとき、必ずここまで掘る）:

- 他に候補はありましたか。何と比べましたか
- 選ばなかった選択肢は、なぜ選ばなかったんですか
- 決めるときに、何を一番優先しましたか。逆に何は諦めましたか
- チーム内で反対意見はありましたか。どう合意しましたか
- 制約（納期、人数、既存システム、社内のルール）はどう効いていましたか
- その判断は、結果として正しかったと思いますか。どこでそう思いましたか

「良さそうだったので」「一般的なので」で止まった場合:

- 「良さそう」と思えた理由を、もう少し細かく言うと何でしたか
- そのプロジェクトの事情で言うと、それが合っていたのはどこですか

## 定性的な成果を言語化する

数値が出ないときの型は「**前はこうだった → 後はこうなった**」です。

- それをやる前は、どういう状態でしたか
- やったあと、何がどう変わりましたか
- **誰が**、**何をできるようになりました**か（あるいは、しなくてよくなりましたか）
- その変化に気づいたのは、どういう出来事でしたか
- もしそれをやっていなかったら、いまどうなっていたと思いますか
- 周りの反応はどうでしたか。誰から何と言われましたか
- その仕組みは今も使われていますか

「好評だった」「感謝された」で止まった場合:

- 誰に、どういう場面で言われましたか
- その人は、それまで何に困っていたんですか

数値を探すヒント（本人が数えていないだけのことが多い）:

- 時間（作業時間、リードタイム、レスポンス時間、リリース頻度）
- 回数（問い合わせ件数、障害件数、手戻り回数、デプロイ回数）
- 規模（コード行数、テーブル数、対象ユーザー数、移行したデータ件数）
- 期間（何ヶ月のプロジェクト、何日で作った）

## 失敗・改善の余地を引き出す

- そのプロジェクトで、うまくいかなかったことは何でしたか
- 今の自分がもう一度やるなら、どこを変えますか
- あとから「あれは失敗だったな」と思った判断はありますか
- 想定外だったことはありましたか。どう対処しましたか
- レビューや運用で、あとから指摘されたことはありましたか
- 残したままになっている技術的負債はありますか。それはなぜ残ったんですか

言いにくそうにしている場合:

- 減点にはなりません。むしろ企業は「気づいて次に活かせる人」を評価します
- 完璧だったプロジェクトはないので、当時の制約でやむを得なかった話でも構いません

## 地味な経験を発掘する

「他にありますか」では出てきません。具体例を挙げて心当たりを聞きます。

- 障害やトラブルの対応をしたことはありますか。原因はどう突き止めましたか
- 手作業でやっていたことを、自動化したり楽にしたりしたことはありますか
- 監視やログまわりを触ったことはありますか
- 手順書やドキュメントを整備したことはありますか
- コードレビューはしていましたか。どういう観点で見ていましたか
- 新しく入った人のサポートやオンボーディングをしたことはありますか
- 社内で「こうしませんか」と提案して通ったことはありますか
- 社内勉強会やLTで話したことはありますか。テーマは何でしたか
- ブログ記事やQiita、Zennを書いたことはありますか
- OSSにPRを出したり、Issueを立てたりしたことはありますか
- 個人開発や、趣味で作ったものはありますか
- 業務で少しだけ触った技術、検証だけした技術はありますか
- 業務外で学んでいること、読んだ本、取った資格はありますか

出てきたら「それは載せなくていいです」と本人が言っても、記録だけはしてください。
載せるかどうかの判断は後工程で行います。

## キャリアビジョンを掘る

志向性:

- どういう仕事をしている時が一番楽しいですか
- 直近で「これはやってよかった」と思えた仕事は何でしたか。何がよかったんですか
- 逆に、やっていてつらい・気が乗らないのはどういう仕事ですか
- 作るのが好きですか、直すのが好きですか、仕組みを整えるのが好きですか
- 一人で深く掘るのと、チームで動かすのと、どちらに手応えがありますか

将来像:

- 3年後、どういう立ち位置で働いていたいですか
- 5年後はどうですか。3年後の延長ですか、それとも別の方向ですか
- 目指したい役職はありますか（テックリード、EM、PdM、SRE、アーキテクトなど）
- まだ経験していないけど、やってみたい領域はありますか
- 憧れているエンジニアや、こうなりたいと思う人はいますか。その人のどこがですか

短期:

- 次の職場で、まず何をやりたいですか
- 逆に、次の職場で「これはもうやりたくない」ことはありますか

接続（**必ず聞く**）:

- そう思うようになったきっかけは、これまでのどの経験ですか
- <案件名>のあの経験と、いまの話はつながっていますか
- その考えを持つ前と後で、仕事の仕方は変わりましたか

## 答えが浅いときの汎用フレーズ

- そこをもう少し具体的に聞かせてください
- 例えばどういう場面でしたか
- そのとき、あなたは何を考えていましたか
- 一番大変だったのはどの部分ですか
- それは誰が決めたことですか
- 差し支えなければ、実際のやり取りに近い形で教えてください
- 固有名詞は伏せて構わないので、技術的に何をしたかだけ教えてください
