# テクニカルスキルの棚卸し

`resume.md` の「テクニカルスキル」に載せる内容を整理するための下書きです。習得の背景や具体的な利用場面など、`resume.md` には書ききれない詳細をここにメモしておきます。

すべて `docs/projects/`・`docs/activities.md`・`docs/career-vision.md` に記載のある事実のみを根拠にしています。根拠のない技術（記載のないツール類）は、意図的に載せていません。

載せる対象は、主要な言語・ライブラリ・フレームワーク、Figmaのような広く知られたツール、開発手法、UX・デザインに絞ります。
補助的なツール（Rector、Larastan、PHP_CodeSniffer、Xdebugなど）や個別の外部サービス連携（kintone、Google Calendar APIなど）は、
スキル名としては列挙せず、案件ごとの実績として `docs/projects/` の中で語ります。

## 2つの評価軸

技術そのものと、ツール・手法とでは、測るべきものが違うため軸を分けます。

| 対象 | 軸 |
| --- | --- |
| プログラミング言語・ライブラリ・フレームワーク・ミドルウェア | **レベル1〜5**（独力でどこまで作れるか） |
| ツール・開発手法・UX・デザイン | **どこまで浸透させたか**（自分の仕事や組織にどう組み込んだか） |

ツールや手法は「独力でどこまで作れるか」では価値が測れません。
たとえばFigmaは、機能をどれだけ知っているかより、チームの合意形成の仕組みとして定着させられたかの方が実態を表します。

## レベルの定義（言語・ライブラリ・フレームワーク・ミドルウェア）

自己流の基準にせず、次の2つの既存モデルを土台にします。

- **ドレイファスモデル（技能習得の5段階）**: 初心者／中級者／上級者／熟練者／達人。
  経験年数ではなく「何を根拠に判断しているか」で段階を分ける点を採用する
- **ITスキル標準（ITSS／IPA）**: レベル2「上位者の指導の下で作業できる」、
  レベル3「要求された作業をすべて独力で遂行できる」、レベル4「独力で課題を発見し、解決をリードできる」
  という区切りを採用する

この2つを重ねて、5段階を次のとおり定義します。

| レベル | 対応 | 定義 |
| --- | --- | --- |
| Lv.1 | 初心者 / ITSS 1 | 学習・調査の段階。チュートリアルや短い検証で触ったことがある、既存の仕組みを利用したことがある、という程度 |
| Lv.2 | 中級者 / ITSS 2 | 前例に沿って手を動かせる段階。既存の構成・設計に従った実装や改修はできるが、選定や全体設計は他者・既存方針に依存している |
| Lv.3 | 上級者 / ITSS 3 | 独力で完結できる段階。要件から設計・実装まで一人で遂行でき、なぜその技術・その構成を選んだのかを自分の言葉で説明できる |
| Lv.4 | 熟練者 / ITSS 4 | 課題を発見し解決をリードできる段階。性能・保守性といった非機能面やトラブルにも対処でき、根本原因まで遡って設計を見直せる。手法をチーム・社内へ展開できる |
| Lv.5 | 達人 / ITSS 5以上 | 第一人者の段階。OSSや社外コミュニティに対して継続的に影響を与えている |

### レベルを判定するときの軸

- **業務か個人開発かでレベルを分けない。** 判定するのは「どこまで自分で判断したか」であって、
  仕事で使ったかどうかではない。個人開発でも、自分で技術選定を行い、その理由を説明でき、
  アプリケーションとして設計・実装をやり切っているならLv.3とする。
  逆に業務であっても、既存の構成に沿って改修しただけならLv.2にとどまる
- **経験年数では判定しない**（ドレイファスモデルの考え方）。長く使っていても、
  与えられた前例のとおりにしか書けないならLv.2
- **Lv.1は「触っただけ」に限る。** 導入検討のための検証や、既存環境をそのまま利用しただけのものが該当する
- ただし、**運用実績の有無は備考に必ず書く。** 個人開発のTRPG向け日程調整ツールは現在も開発中で未リリースのため、
  同ツールで使っている技術には不特定多数を相手にした本番運用の経験がない。レベルとは別の情報として明示する

## 浸透の度合いの定義（ツール・開発手法・UX・デザイン）

| 段階 | 定義 |
| --- | --- |
| 個人で実践 | 自分の作業の中では使っている。他のメンバーが使える状態にはなっていない |
| プロダクト・チームに適用 | 開発フローや成果物に組み込み、チームで使われる状態にした |
| 組織へ展開・社外へ発信 | 上記に加えて、社内の他チームへ広げた、あるいは登壇・執筆で社外へ出した |

段階の線引きが難しい場合は、**「自分以外の人が使っている状態を作れたか」**を基準に判断します。

現時点でLv.5に該当するスキルはありません。

## 開発手法

| スキル | 浸透の度合い | 習得の背景・利用場面 |
| --- | --- | --- |
| アプリケーションレイヤーの設計 | 組織へ展開・社外へ発信 | 本人が最も自信を持つ領域。腐敗防止層と依存性の逆転、複雑な配列の扱い、設計とビジネスの関係などをテックブログで継続的に発信している |

| TDD | 個人で実践・社外へ発信 | 業務で試したうえで、社外LTとテックブログで発信した。チームの開発フローとして定着させるところまでは至っていない |
